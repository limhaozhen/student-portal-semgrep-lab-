#3HighFalse positive (mitigated) python.flask.security.injection.nan-injection.nan-injection

portal/assignments.py:299 · rule

297    feedback = (request.form.get("feedback") or "").strip()
298    try:
299        score = float(request.form.get("score", ""))
300        if not math.isfinite(score) or not 0 <= score <= s["max_score"]:
301            raise ValueError
MessageFound user input going directly into typecast for bool(), float(), or complex(). This allows an attacker to inject Python's not-a-number (NaN) into the typecast. This results in undefind behavior, particularly when doing comparisons. Either cast to a different type, or add a guard checking for all capitalizations of the string 'nan'.
CWECWE-704: Incorrect Type Conversion or Cast
OWASP-
Confidence / Likelihood / ImpactMEDIUM / MEDIUM / MEDIUM
Rule typevuln · Improper Validation
Triagefloat(request.form['score']) is followed immediately by math.isfinite() and a 0..max_score range check, so 'nan', 'inf' and out-of-range values raise ValueError and are rejected with an error message (tested: score 999 is refused).
RemediationKeep the isfinite() guard on every float() of user input. Optional: validate the raw text with a strict regex such as ^\d{1,4}(\.\d{1,2})?$ before converting.
References
  • https://discuss.python.org/t/nan-breaks-min-max-and-sorting-functions-a-solution/2868
  • https://blog.bitdiscovery.com/2021/12/python-nan-injection/
